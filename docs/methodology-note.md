# Design Process Methodology Note

## Sketching & Prototyping Approach

Our group followed an iterative design process that began with low-fidelity sketches before moving into digital design and implementation. The initial sketches were used to explore the system's basic structure, layout, navigation, and user interactions without focusing heavily on visual styling or implementation details.

These early sketches gave the team a decent foundation and a clear idea of how the system should be structured before proceeding to the actual digital design and development stages.

## What we actually did:
**1:Low-Fidelity Sketching**

We initially created rough, low-fidelity sketches to explore the main screens, layouts, navigation flow, and placement of key system elements. The sketches allowed us to quickly experiment with different ideas and identify potential usability issues before committing to the final design.

**2:System Flow and Information Architecture**

After establishing the basic screen concepts through sketches, we developed the system flowchart and information architecture to define how the different screens and system components would relate to one another.

**3:Digital Prototyping in Figma**

The ideas and layouts developed during the sketching stage were then translated into digital prototypes using Figma. This stage allowed us to refine the layouts, improve consistency, establish the visual hierarchy, and create more detailed representations of the final system.

**4:Implementation of the Actual System**

The digital designs provided a practical reference for implementing the actual system. The initial sketches were therefore not treated as isolated deliverables, but as an early design foundation that helped guide the progression from an initial concept to the implemented interface.

**Why this is still a defensible process:**
- The **flowchart and IA diagram** (see `docs/`) served the same planning function that sketches typically serve — establishing structure, navigation, and screen relationships before visual design began — just in a more structured, diagram-based form rather than freehand drawing.
- Working directly in Figma allowed faster iteration on layout and content once structure was agreed, given the team's tool proficiency.

**Where genuine low-fidelity sketching is majorly focused**
The low-fidelity sketches were particularly useful because they allowed the team to focus on functionality and user flow before visual details. Since changes at the sketching stage are quick and inexpensive, we were able to explore different interface arrangements and determine what information and actions should be presented on each screen.

The sketches consequently provided a decent craft idea of the system's interface and interaction structure, which guided the subsequent Figma designs and the implementation of the actual system.

The overall design progression can therefore be summarized as:

Low-Fidelity Sketches → System Flow & Information Architecture → Figma Prototype → Actual System Implementation

This approach helped ensure that the implemented interface was based on an established design concept rather than being developed entirely from the beginning without prior planning.

The assignment brief specifies Balsamiq as the default prototyping tool. The group requested and received lecturer approval to use Figma instead. Confirmation of this approval is kept in the docs/ directory alongside the relevant design documentation.

Figma was used to translate the concepts developed during the low-fidelity sketching stage into more detailed digital prototypes that could subsequently guide implementation.
